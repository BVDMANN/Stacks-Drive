# ADR 0025 — Prix sur distance routière OSRM (remplace l'ADR 0010)

- **Statut :** acceptée (15/11/2026, v2.50 — décision du propriétaire : « Distance route d'abord, puis pousse »).
- **Contexte :** depuis la v2.11, l'estimation était calculée sur la distance à vol d'oiseau (haversine) entre les centres des quartiers, puis entre les points exacts (v2.47) — par respect de l'ADR 0010 (« le prix ne doit jamais dépendre d'OSRM »). Le propriétaire tranche le 15/11 ~09h53 : le prix doit refléter la route réelle. Les trajets sinueux de Libreville (détours par la N1, quartiers en cul-de-sac) coûtent plus cher à vol d'oiseau qu'en réalité : l'estimation sous-évaluait systématiquement les courses longues, et le chauffeur qui proposait le « vrai » prix paraissait cher face à une estimation trop basse. L'écart mesuré le 15/11 (OSRM, centres de quartiers) : Aéroport → Centre-ville 10,62 km par la route contre 8,90 km à vol d'oiseau (+19 %) ; Glass → Nzeng-Ayong 9,84 contre 6,26 (+57 %) ; Akanda → Aéroport 22,30 contre 7,96 (×2,8 — la route contourne par la N1, le vol d'oiseau traverse la forêt). L'ancre Centre-ville ↔ Nzeng-Ayong (Solo 1 500 / Groupe 950, v2.16) ne doit PAS bouger : c'est une valeur fixe, pas un calcul — la distance routière réelle (6,56 km) donnerait 1 900 / 1 200 avec le modèle au km.

## Décision

1. **Distance = distance ROUTIÈRE OSRM entre les points exacts** (départ et destination, épingle déplacée comprise). Le modèle au km est INCHANGÉ : Solo 500 + 210 FCFA/km, Groupe 300 + 135 FCFA/km, planchers 550/400, suppléments aéroport 800/300 et piste 800. Seule la distance change — les estimations montent sur les trajets sinueux, c'est attendu et assumé.
2. **Le prix est calculé et revalidé CÔTÉ SERVEUR uniquement** — un seul estimateur (`lib/estimate-server.ts` : `estimateTripServer` / `estimateFromRoute`), utilisé par `POST /api/estimate` (affichage client), `POST /api/rides` (création de la demande — distance et durée stockées en base, migration v2.50) et `PATCH /api/proposals/[id]` (revalidation à l'acceptation sur les points exacts). **Le client ne calcule plus jamais un prix seul** : il envoie les deux points et les deux quartiers à `/api/estimate` (debounce 400 ms, annulation de l'appel précédent) et affiche ce que le serveur renvoie — le même trajet donne le même prix des deux côtés. Les anciennes fonctions synchrones `estimateFare` / `estimateFareFromCoords` (`lib/pricing.ts`) sont SUPPRIMÉES ; `estimateFareForDistance` prend désormais une distance routière (options `durationMin`, `approximate`, `anchor`).
3. **Ancre FIGÉE** : Centre-ville ↔ Nzeng-Ayong = Solo 1 500 / Groupe 950, dans les deux sens, quelle que soit la distance routière — un dépassement explicite dans le calcul (`isAnchorTrip` + option `anchor` de `estimateFareForDistance`, constantes `ANCHOR_SOLO` / `ANCHOR_GROUPE` dans `lib/pricing.ts`), pas une coïncidence de coordonnées. Le supplément aéroport reste déterminé par le QUARTIER (départ ou destination = Aéroport Léon-Mba), comme avant.
4. **REPLI explicite quand OSRM est indisponible** (serveur démo public, 1 req/s, non commercial) : distance à vol d'oiseau entre les points exacts, et l'estimation est marquée `approximate: true` (`distanceSource: 'haversine'`). L'interface l'affiche (« Estimation approximative », `HomeScreen`, `PoiInfoCard`) ; le serveur le journalise (audit `fare_computed` : `approximate`, `distanceSource`). Si la route API elle-même est injoignable, le client garde sa dernière estimation affichée, ou affiche « Estimation indisponible » — jamais de prix calculé en local, jamais de plantage silencieux. Le repli est appliqué côté serveur aussi (`estimateFromRoute` sur une route `fallback`), pour que client et serveur restent d'accord.
5. **Cache + espacement** : `/api/estimate` met en cache 5 min par trajet (mêmes coordonnées arrondies + quartiers + options) ; l'espacement OSRM (1,1 s) est centralisé dans `fetchRoadRoute` (`lib/routing.ts`) — les routes API n'ont plus à l'appliquer elles-mêmes (`/api/route` simplifiée en conséquence).

## Conséquences

- Les estimations montent sur les trajets sinueux (mesures OSRM 15/11, centres de quartiers ; anciennes valeurs = haversine) : Aéroport → Centre-ville Solo 3 150 → 3 550, Groupe 1 800 → 2 050 ; Glass → Nzeng-Ayong Solo 1 800 → 2 550 ; Charbonnages → Owendo Solo 3 050 → 4 300 ; Akanda → Aéroport Solo 2 950 → 6 000 ; Nzeng-Ayong → Owendo Solo 2 700 → 3 700 ; Centre-ville → PK12 Solo 2 100 → 2 700 ; Centre-ville → Nkoltang Solo 6 450 → 7 400 (piste comprise). L'ancre ne bouge pas (1 500 / 950).
- Le revenu moyen par course (hypothèse du doc financier, mix 50/30/20) passe de 2 486 à **3 568 FCFA** — les projections du doc financier sont régénérées par `docs:sync` (miroir mis à jour : table `ROAD_KM` des distances mesurées + override ancre + durées OSRM). Les projections restent des hypothèses, jamais des tarifs.
- La distance et la durée affichées sur la page de course (`/courses/[id]`) préfèrent désormais la route OSRM déjà récupérée ; la pop-up de demande chauffeur (`RequestPopup`) affiche la distance routière (repli vol d'oiseau en attendant la route) ; la mini-carte d'info d'un lieu (`PoiInfoCard`) passe par `/api/estimate` elle aussi.
- Le prix dépend désormais d'un service externe (OSRM démo) : une panne OSRM ne bloque rien (repli explicite), mais les estimations sont alors approximatives. L'auto-hébergement OSRM sur VPS (ADR 0002) devient plus urgent : il conditionne la fiabilité du prix, pas seulement l'affichage.
- Deux points du même quartier donnent toujours des estimations différentes (points exacts) — et désormais cohérentes avec la route réelle.

## Alternatives écartées

- **Garder haversine pour le prix, OSRM pour l'affichage** (ADR 0010) : écarté par la décision du propriétaire — l'estimation sous-évaluait les trajets sinueux et mettait le chauffeur en porte-à-faux face au passager.
- **Prix sur durée OSRM** : rejeté avec le modèle au km (ADR 0005) — pas de prix à la minute ; la durée reste affichée, jamais facturée.
- **Recalibrer le modèle au km pour compenser la hausse** : écarté — le modèle au km (500 + 210, 300 + 135) est la référence affichée depuis la v2.11 ; la hausse vient de la distance réelle, pas d'un changement de tarif. L'ancre, elle, est figée par décision, pas recalibrée.
- **Estimation indisponible quand OSRM est down** (pas de repli) : écarté — une panne OSRM bloquerait toutes les commandes. Le repli vol d'oiseau marqué approximative garde l'appli utilisable et honnête.
